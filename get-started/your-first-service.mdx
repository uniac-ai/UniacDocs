This walkthrough deploys the same service as the [Quickstart](/quickstart),
explaining what each piece is as you go. You need the CLI
[installed](/get-started/installation) and a [login session](/get-started/login).

## Scaffold

```bash
mkdir hello-uniac && cd hello-uniac
uniac init
```

`uniac init` asks for a service name and writes `uniac.yaml`. It refuses to
overwrite an existing manifest.

```yaml uniac.yaml
runtime: yaml
default: main
resources:
  hello:
    type: service
    image: nginx:alpine  # any OCI image reference
  main:
    type: deployment
    services:
      hello: { from: hello }
```

Two resources, two roles:

- `hello` is a **service** — a reusable definition of one workload's shape:
  which image, which environment, which start command. A service is never
  deployed directly.
- `main` is a **deployment** — an instantiation of services. It is what
  `uniac deploy` targets; `default: main` makes it the target when you don't
  name one.

The separation matters once systems grow: one definition can be instantiated
many times, under different names, with different public exposure. See
[Services](/concepts/services) and [Deployments](/concepts/deployments).

## Claim public exposure

As scaffolded, the service would be reachable only from other services in the
same project. Exposure is claimed on the *instance*, in the deployment:

```yaml uniac.yaml {8}
runtime: yaml
default: main
resources:
  hello:
    type: service
    image: nginx:alpine
  main:
    type: deployment
    services:
      hello:
        from: hello
        public_ports: [{ port: 80, type: http }]
```

`port` is the port your process listens on — nginx serves on 80. `type: http`
asks the platform to terminate HTTPS on a public hostname and route requests to
that port. See [Endpoints](/concepts/endpoints) for the `tcp` alternative.

## Plan

```bash
uniac plan
```

```text
Deployment: main
Artifact:   sha256:2e462d2fe307

Building
  pull nginx:alpine

Deploying
  hello  nginx:alpine  public: 80 (http)
```

`plan` resolves the manifest into the **deployable** — the exact artifact the
platform will consume — and prints its content digest. It runs fully offline
and applies every rule decidable from the manifest alone, so it is the
verification loop: edit, plan, read the error, fix. A manifest that passes
`plan` cannot fail `deploy` on a manifest error.

The digest is content-addressed: reindenting the file or reordering resources
does not change it. A digest that moved means the system actually changed.

## Link and deploy

```bash
uniac link
uniac deploy
```

`link` binds this directory to a remote project (stored in
`.uniac/deploy.json` — gitignore it; it is per-checkout state, not source).
`deploy` resolves the manifest again, pulls the image with your local Docker,
pushes it to the project registry, registers the deployment, and polls until
the platform settles — up to five minutes, every two seconds. The run ends
with the state block:

```text
project  hello-uniac-a1b2c3d4

service  hello  v1
  image  nginx:alpine
  digest  sha256:…
  status  running (1/1)
  endpoint  https://<allocated-host>.svc.uniac.ai → :80
```

`v1` numbers the serving deployment. `endpoint` is the whole address to dial;
`→ :80` names your own listen port that traffic lands on. Open the address —
that's nginx, running on Uniac.

## Observe, change, redeploy

```bash
uniac status
```

reports the same state block any time, and changes nothing.

Edit the manifest — bump the image tag, add an `env` block — then:

```bash
uniac plan      # check what changed: the digest moved
uniac deploy    # ship it: the service moves to v2
```

A redeploy that leaves `public_ports` out keeps the exposure you already
claimed; see [Endpoints](/concepts/endpoints) for the full redeploy semantics.
