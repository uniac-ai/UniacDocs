`uniac.yaml` sits at the project root and is the whole static description of a
system — one file, read by every command. Decoding is strict: an unknown key
anywhere is a hard error, so the field tables below are exhaustive, and an
invented field (`ports`, `replicas`, `volumes`, `depends_on`) fails the
manifest rather than being ignored.

Everything on this page is enforced by `uniac plan`, which runs fully offline:
write, plan, read the error, fix.

```yaml uniac.yaml
runtime: yaml
default: shop
resources:
  worker:
    type: service
    image: "mendhak/http-https-echo:31"
    env:
      GREETING: hello

  shop:
    type: deployment
    services:
      web:
        from: worker
        public_ports: [{ port: 8080, type: http }]
```

## Top level

| Field | Meaning |
|---|---|
| `runtime` | Manifest runtime. `yaml` is the only supported value, and the default. |
| `default` | The resource `uniac plan` / `uniac deploy` act on when none is named. Must name a deployment. |
| `resources` | Named map of typed resources — the system description. Required. |

Target resolution for both commands: the named resource, else `default`, else
the manifest's only deployment. With several deployments and no `default`, the
run fails and lists them.

**Resource names** match `^[a-z0-9]+(?:(?:__?|-+)[a-z0-9]+)*$` — lowercase
alphanumeric runs joined by interior separators (`-`, `--`, `_`, `__`), which
may never lead or trail. The grammar is the docker-repository-safe subset,
because instance names become image repository components. The same grammar
constrains service instance names.

## `type: service` and `type: stateful`

Both declare a reusable [service definition](/concepts/model#service) with the
same body; `stateful` additionally caps the running service at a single
instance.

| Field | Required | Meaning |
|---|---|---|
| `image` | yes | OCI image reference. Prebuilt only: there is no build-from-source field. |
| `env` | no | Environment variables, `NAME: value`. Values may embed references. |
| `start_command` | no | Overrides the image CMD at the platform layer; the image is untouched. |

There is no port field and no exposure field on a service — exposure is a
property of the deployment (`public_ports`, below), and the internal network
is port-transparent.

**Env key grammar** is `^[A-Za-z_][A-Za-z0-9_]*$`. The key `host` is reserved —
it is the builtin `${{self.host}}`, and declaring it is a config error.

## References

Env values may embed references, resolved by the platform at deploy time and
injected at container start. One grammar everywhere: `${{scope.VAR}}`, where
`scope` is `self` or an instance name, and `VAR` is a declared variable or
the builtin `host`.

```yaml
env:
  OWN_URL:      "http://${{self.host}}:8080"        # own builtin
  GREETING_ALT: "${{self.GREETING}}"                # own variable
  DB_HOST:      "${{database.host}}"                # another instance's builtin
  DATABASE_URL: "${{database.DATABASE_URL}}"        # another instance's variable
```

- **Scope names an instance, not a definition.** `${{database.X}}` names the
  deployed instance `database`, whatever service resource it draws `from`.
  Getting this backwards is the most common wiring bug.
- **`host`** is the only builtin — the platform-allocated internal hostname,
  the one fact the platform contributes to the environment.
- **Names resolve at plan time; values resolve at deploy time.** `uniac plan`
  verifies every reference to `self` or to an instance in the deployed set.
- **No escape syntax exists.** Any `${{` that does not parse as a reference is
  an error, so a literal `${{` cannot appear in an env value.

Because no service declares a port, a consumer cannot derive one — have the
provider export the whole connection string and reference that.

### Cross-deployment references

A reference to a name *outside* the deployed set passes through unresolved and
is resolved remotely against the project's other services. This is how
services in separate deployments wire together — and why a typo in one cannot
be caught locally. **A dangling reference never fails a deploy**: the variable
is left unset and the run reports a `warning` line in the state block.

After a successful deploy the platform re-resolves the project's other
services and recreates any whose injected values changed, so deploy order is a
convenience: a consumer deployed before its provider heals once the provider
lands.

## `type: deployment`

Instantiates services and resolves to the deployable.

| Field | Meaning |
|---|---|
| `services` | Map of instance name → instantiation. At least one is required. |
| `services.<name>.from` | The service resource this instance draws from. Required. |
| `services.<name>.public_ports` | Public-exposure claim set for this instance. Tri-state, below. |

`uniac deploy` rejects a deployment instantiating more than one service; a
multi-service system is several deployments in one manifest, deployed one at
a time and wired by cross-deployment references.

### `public_ports`

Each claim names your process's own listen port and the kind of ingress. Both
keys are required; a bare integer is rejected at parse time.

| Kind | What the platform does | Dial |
|---|---|---|
| `http` | Terminates HTTPS on a public hostname and routes to port `N`. | `https://<hostname>` |
| `tcp` | Allocates a public `host:port` and forwards raw TCP to `N` as-is. | `<hostname>:<allocated-port>` |

The hostname — and for `tcp`, the public port — are the platform's to choose;
read them back from the `endpoint` lines of the [run output](/cli/output).
Port ranges (1..65535) and the at-most-one-port-per-type cap are platform
policy, enforced at deploy time — they pass `plan`.

### The claim set is tri-state

| Written | Meaning |
|---|---|
| omitted | Claims nothing. The platform keeps the serving deployment's claims, so a code-only rollout never drops exposure. |
| `[]` | Claims nothing *and converges* the instance to no public exposure of any kind. |
| present | Restates the full claim set; the result is exactly what is listed. |

A present list is the whole truth: dropping one entry from a two-entry list
retracts that exposure. Never "clean up" a `public_ports` block you did not
intend to change. And expose only the edge — a service with no `public_ports`
is reachable from the project's other services by instance name, which is the
correct default for databases, caches, and internal APIs.

## What fails at plan time

Every message below is produced offline, before anything is sent anywhere.

| Condition | Error |
|---|---|
| Unknown field anywhere | `field ports not found in type registry.serviceSchema` |
| Unknown resource `type` | `unknown type "widget" (supported: service, stateful, deployment)` |
| `runtime` other than `yaml` | `runtime "python" is not supported (only "yaml")` |
| Service with no `image` | `service "a" declares no image` |
| Reserved env key | `env key "host" is reserved for ${{self.host}}` |
| Malformed reference | `malformed reference at "${{ Bad.VAR }}" — expected ${{service.VAR}} or ${{self.VAR}}` |
| `${{self.X}}` with no such own variable | `env U references ${{self.MISSING}} but no such variable is declared` |
| Reference to an in-set instance's missing variable | `env U references database.NOPE, but "database" declares no such variable (available: host, DATABASE_URL)` |
| Unknown ingress kind | `public port 80 claims unknown exposure kind "grpc" (supported: http, tcp)` |
| Bare integer in `public_ports` | `cannot unmarshal !!int 8080 into registry.publicPortSchema` |
| Instance drawing from a missing definition | `instance "a": no service "nope"` |
| Deployment instantiating nothing | `resource "d" must instantiate at least one service` |
| Targeting a service | `resource "api" is a service — services are reusable definitions, not directly deployable` |
| `default` naming a service | `default "api" is a service — only deployments are deployable targets` |
| Name outside the grammar | `resource name "Bad-Name-" must match ^[a-z0-9]+(?:(?:__?\|-+)[a-z0-9]+)*$` |
| Manifest with no deployment | `uniac.yaml declares no deployment — services are reusable definitions` |
| Several deployments, no `default` | `uniac.yaml has multiple deployments and no 'default'; name one (have: d1, d2)` |

What is **not** checked locally: any reference to a name outside the deployed
set — it passes through by design and surfaces at deploy time as a warning,
never a failure.

## The deployable

`uniac plan --json` prints `{resource, digest, deployable}`. The deployable is
the canonical, target-free artifact the platform consumes:

```json
{
  "kind": "deployable",
  "services": [
    {
      "container": { "source": { "ref": "mendhak/http-https-echo:31" } },
      "env": { "GREETING": "hello" },
      "name": "web",
      "public_ports": [{ "port": 8080, "type": "http" }]
    }
  ]
}
```

The digest is content-addressed: services are name-sorted, claim lists
canonicalized, env keys ordered — so reindenting the YAML or reordering
resources produces a byte-identical artifact and the same digest. Read the
deployable, not the YAML, when you need to know what will actually ship.
