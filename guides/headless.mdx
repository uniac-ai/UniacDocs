---
title: "Headless operation"
description: "Running uniac from CI and scripts."
---

Two variables make a run fully non-interactive:

```bash
export UNIAC_ACCESS_TOKEN="…"                 # bypasses interactive login
export UNIAC_PROJECT_URL="my-app-e5f6g7h8"    # full URL or bare slug; bypasses the link binding
uniac deploy
```

Without a link binding and without `UNIAC_PROJECT_URL`, `uniac deploy` drops
into the interactive project picker — which hangs a non-interactive caller, so
always set one of them in CI. Mint a token for `UNIAC_ACCESS_TOKEN` with
`uniac auth token` on a machine where you are logged in.

## Environment variables

| Variable | Effect |
|---|---|
| `UNIAC_ACCESS_TOKEN` | Bypasses interactive login. |
| `UNIAC_PROJECT_URL` | Targets a project by full URL or bare slug, bypassing `.uniac/deploy.json` and the picker. |
| `UNIAC_PROGRESS` | `1` forces progress narration on stderr, `0` silences it. Never affects stdout. |
| `UNIAC_STORE_DIR` | Local artifact store location (default `~/.uniac/store`). |
| `UNIAC_AUTH_HOST` | The host serving the `/cli/auth` login handoff (default `uniac.ai`). |

## Scripting a deploy

`deploy` and `status` end with a [state block](/cli/output) on stdout and a
typed [exit status](/cli/exit-codes). Branch on the exit status; read the
state block for detail:

```bash
uniac deploy
case $? in
  0) echo "deployed" ;;
  9) echo "platform unreachable — retry with backoff" ;;
  *) echo "failed — see the error lines above" >&2; exit 1 ;;
esac
```

Progress narration is written to stderr only when stderr is a terminal, so CI
logs stay clean by default; set `UNIAC_PROGRESS=1` to see live progress in CI
logs anyway. Docker must be available on the runner — `deploy` pulls the
declared image with the runner's own Docker credentials before pushing it to
the project registry.

Interrupting a deploy does not cancel the platform-side work; run
`uniac status` to see where it landed.
