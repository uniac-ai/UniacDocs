By the end you will have a container deployed and reachable at a public URL.
You need Node 18+, a running Docker daemon, and a prebuilt container image —
Uniac deploys images, it does not build them.

## 1. Install and log in

```bash
npm i -g @uniac/cli
uniac auth login
```

`login` opens a browser and stores the session in `~/.uniac/auth.json`. For
machines without a browser, see [Agentic development](/guides/agents).

## 2. Scaffold a manifest

```bash
uniac init
```

Asks for a service name and writes `uniac.yaml`: one service plus the
deployment that instantiates it. Set `image` to your own, or keep the
scaffold's `nginx:alpine` to try the flow:

```yaml uniac.yaml
runtime: yaml
default: main
resources:
  hello:
    type: service
    image: nginx:alpine
  main:
    type: deployment
    services:
      hello:
        from: hello
        public_ports: [{ port: 80, type: http }]
```

## 3. Plan

```bash
uniac plan
```

Runs fully offline and prints what would ship:

```text
Deployment: main
Artifact:   sha256:2e462d2fe307

Building
  pull nginx:alpine

Deploying
  hello  nginx:alpine  public: 80 (http)
```

Run it after every manifest edit; a manifest that fails `plan` fails `deploy`
with the same error.

## 4. Deploy

```bash
uniac link
uniac deploy
```

`link` binds the directory to a remote project. `deploy` pulls the image with
your local Docker, pushes it to the project registry, registers the
deployment, and watches until it settles, ending with the state block:

```text
project  my-app-e5f6g7h8

service  hello  v1
  image  nginx:alpine
  digest  sha256:…
  status  running (1/1)
  endpoint  https://<allocated-host>.svc.uniac.ai → :80
```

Open the `endpoint` address — that's your service.

## 5. Observe

```bash
uniac status
```

Reports the same state block at any time; changes nothing.
